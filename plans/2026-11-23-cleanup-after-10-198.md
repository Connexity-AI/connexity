## Goal

Six known gaps were left when the old test runner was removed (10.198). After this
merges none of them is left: nothing an API caller can reach answers 500 for a delete,
no code or column stays that nothing uses, the plan check has no exemption for
automation that no longer exists, and the guide an assistant reads points at a page
that exists.

## Changes

Each item of the roadmap row, with what the code shows today (checked on `main`,
2026-11-23).

1. **Deleting an agent that has calls answers 500.** No longer reachable: there is no
   route, MCP tool or screen that deletes an agent. Nothing to change; the item is
   closed by this finding.
2. **Deleting an integration with linked agents answers 500.** Still true:
   `DELETE /api/v1/integrations/{id}` removes the row while `agent.integration_id` and
   `call.integration_id` still point at it, so the database refuses and the caller gets
   a 500. Nothing in the web app or the MCP server calls this route, or any other route
   of the `/integrations` router (the assistant connects a voice platform through
   `connect_voice_platform`, which uses its own route). **The route answers 409 with the number of agents that use the
   connection, and deletes only a connection no agent uses.** The six routes stay: they
   are the only way to connect n8n and list its workflows (see Decisions).
3. **Three uncalled methods on the simulation runtime interface.** Confirmed:
   `supported_for_platform` and `test_connection` have no caller, and `validate_config`
   is called only from `test_connection`. All three are deleted from the interface and
   its implementations, with the `RuntimeTestResult` type only they use.
4. **The unused `eval_config.config` column.** Confirmed: nothing reads or writes it.
   The column is dropped (migration `0047`) and removed from the model.
5. **The plan gate still exempts release-please branches.** Confirmed in
   `.github/workflows/plan.yml`. The repo has no release-please workflow or
   configuration any more (releases are cut by hand through `release-platform.yml`), so
   the exemption is removed. The `no-plan` label stays.
6. **The MCP connect guide still names the Readiness screen.** Confirmed in
   `guides/connect.md`, and the same wording in `docs-internal/mcp-architecture.md` and
   one code comment. They name the Work page ("Assistant connected", "Show how") now.

Also in this change, because the file is touched for its neighbour: the line in
`docs-internal/deployment.md` that says the email sender name is added later is
corrected; it was set on 2026-11-23.

## Decisions

1. **Decided (Dmytro, roadmap row, 2026-11-20):** these six items are one clean-up row.
2. **Proposed:** item 1 needs no code, because nothing can delete an agent.
3. **Decided (Dmytro, 2026-11-23, "Keep them, refuse with 409"):** the routes stay and a
   delete of a connection in use is refused. Dmytro first chose to delete the six
   routes, on my statement that nothing uses them. While building I found they are the
   only way to connect n8n (voice platforms have an assistant tool; n8n has none), told
   him, and he chose this instead.
4. **Open:** an assistant tool to connect n8n. Today it can only be done by calling the
   API directly. Not in this row.
5. **Proposed:** the three runtime methods and the column are deleted, not kept for
   later; voice simulations will define what they need when they are built.

## Out of scope

- A way to delete an agent, a workspace's data or an account's data (roadmap row
  "Delete workspace data").
- `DELETE /api/v1/users/me`, which deletes the signed-in person with no check of what
  they own. It is not in the row; it belongs to "Delete workspace data" or the Account
  row and is reported here so it is not lost.
- Renaming the `get_readiness` tool or the Readiness steps: the tool reports setup
  progress and still exists; only the screen was deleted.

## Risks

- **Dropping a column cannot be undone for its data.** Checked on the hosted database
  (2026-11-23, counts only): `eval_config` has one row, and its `config` holds an empty
  JSON value, no data. Nothing is lost.
- **A connection in use can never be removed** until its agents are moved or removed,
  and nothing does either today. That is the intended answer for now: a person or an
  assistant is told why, where before the request failed with a server error.
